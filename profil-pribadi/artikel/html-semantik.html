Menyusun struktur HTML yang mudah dibaca

Ditulis oleh Meilani Oktaviana Eka Putri

Waktu pertama belajar HTML, kebiasaan saya masih sederhana: pakai <div> untuk hampir semua hal, lalu diberi nama kelas seadanya seperti box1 atau wrapper2. Halamannya jalan, tapi begitu ditambah beberapa section baru, saya sendiri jadi bingung mencari elemen mana yang mengatur bagian mana.

Kenapa tag semantik penting

Tag semantik seperti <header>, <nav>, <main>, <section>, dan <article> memberi tahu maksud sebuah elemen, bukan cuma bentuknya. Manfaat yang langsung saya rasakan:

  • Kode lebih mudah dibaca ulang — nama tag saja sudah menjelaskan isinya.
  • Screen reader dan mesin pencari bisa memahami struktur halaman dengan lebih baik.
  • Lebih gampang dipetakan ke CSS, karena setiap section punya batas yang jelas.

Kebiasaan yang saya terapkan sekarang

Di proyek web profil ini dan toko Amoura Atelier, saya mulai konsisten memakai satu <section> per topik konten (Tentang, Pendidikan, Keahlian, dst), dengan id yang jelas supaya bisa langsung ditautkan dari menu navigasi. Untuk penamaan kelas, saya coba pakai pola blok__bagian (semacam BEM sederhana) supaya tidak tabrakan antar-section saat file CSS-nya makin panjang.

Ini belum sempurna — masih ada beberapa bagian yang saya tulis ulang begitu ketahuan strukturnya kurang rapi. Tapi dibanding versi pertama dulu, sekarang jauh lebih mudah menelusuri kode saya sendiri setelah beberapa minggu tidak dibuka.
