Database

Hal yang saya pelajari soal database

Ditulis oleh Meilani Oktaviana Eka Putri

Database adalah bagian yang paling banyak membuat saya menghapus dan menggambar ulang skema dari awal. Berikut beberapa kesalahan yang pernah saya buat, dan apa yang akhirnya saya pahami dari sana.

Kesalahan pertama: menaruh semua di satu tabel

Versi paling awal skema toko Amoura Atelier, saya sempat menaruh nama kategori langsung sebagai kolom teks di tabel produk. Kelihatannya lebih simpel, sampai saya sadar kalau nama kategori salah ketik di satu baris, filter berdasarkan kategori jadi tidak akurat. Solusinya: pisahkan jadi tabel kategori sendiri, lalu hubungkan lewat kategori_id sebagai foreign key.

Memahami relasi lewat kasus nyata, bukan teori dulu

Relasi one-to-many baru benar-benar masuk akal buat saya setelah mengerjakan fitur transaksi: satu pesanan bisa punya banyak baris di pesanan_item. Dari situ saya juga belajar kenapa ON DELETE CASCADE penting di beberapa relasi — supaya menghapus satu pesanan otomatis membersihkan seluruh item di dalamnya, tanpa meninggalkan data yatim di tabel lain.

Yang masih terus saya latih

  • Menulis query dengan prepared statement secara konsisten, bukan menyisipkan variabel langsung ke SQL.
  • Membaca rencana eksekusi query sederhana, walau untuk proyek sekecil ini belum terlalu terasa dampaknya.
  • Membiasakan diri membuat migrasi/skrip SQL tambahan saat fitur baru butuh tabel baru, bukan mengubah tabel produksi secara langsung tanpa catatan.

Belum semua konsep saya kuasai, tapi setiap proyek kecil seperti ini membuat kesalahan-kesalahan lama semakin jarang terulang.
